# I love stretch — автозапись в танцевальный зал

Одностраничный сайт: календарь с часовыми слотами, форма брони, онлайн-оплата через ЮKassa
(или перевод по реквизитам), брони хранятся в Google Календаре.

Вся документация в Obsidian: папка `Dance Studio Booking`, начать с заметки «00 I love stretch — обзор».

## Запуск

Нужен Node.js 20 или новее. Сервер работает в **одном экземпляре**: второй запуск остановится с ошибкой
(файл-замок `run/server.lock`). Не запускайте его в кластерном режиме pm2.

```bash
npm install        # пакет nodemailer для писем
cp .env.example .env
npm start          # http://localhost:3000
npm test           # 62 теста
npm run check:mail # проверить вход на SMTP; с адресом в конце отправит тестовое письмо
```

По умолчанию календарь в памяти (`CALENDAR_DRIVER=memory`) с демо-занятостью, а оплата имитируется
(`PAYMENT_PROVIDER=fake`): после «Забронировать» в окне вместо формы ЮKassa появляются кнопки «Оплатить» и «Отказаться».
Так можно пройти весь путь без Google и ЮKassa. В `NODE_ENV=production` имитация запрещена.

## Как проходит бронь

1. Клиент выбирает часы и заполняет форму. Сервер заново проверяет, что время свободно, и считает цену сам.
2. В календаре появляется жёлтое событие «⏳», в ЮKassa создаётся платёж для виджета (`confirmation.type = embedded`).
   Форма оплаты ЮKassa (карта, СБП) открывается прямо на сайте, в окне брони, клиент никуда не уходит.
3. Оплата прошла: ЮKassa присылает уведомление, сервер **сам спрашивает статус у API ЮKassa** (телу уведомления не верит),
   красит событие в зелёный «✅» и пишет клиенту. Виджет сообщает странице, что оплата завершена, страница спрашивает
   у сервера статус и показывает «Бронь подтверждена» или «Бронь снята».
4. Оплата не прошла или клиент ушёл: через `HOLD_MINUTES` событие удаляется, слот освобождается.
5. Если деньги пришли уже после снятия брони, сервер автоматически делает возврат и сообщает администратору.

Уведомление может потеряться, поэтому раз в `SWEEP_INTERVAL_SEC` сервер сверяет все ожидающие брони с ЮKassa.
Администратор по-прежнему может подтвердить бронь вручную, покрасив событие в зелёный.

## Письма

Шаблоны в `server/mail.js`, отправка в `server/notify.js` (SMTP через nodemailer, письма в HTML и простым текстом).

| Когда | Кому | Что внутри |
|---|---|---|
| Бронь создана | клиенту | время, сумма, сколько держится слот |
| **Оплата прошла** | **клиенту** | время, адрес, инструкция: за 15 минут до начала забрать ключ в офисе ITB (3 этаж, офис 307), закрыть окна, свет и дверь, вернуть ключ на стойку ресепшена; кнопка «Открыть на карте»; файл `.ics` для календаря |
| **Оплата прошла** | **администратору** (`ADMIN_EMAIL`, пусто — ящик `SMTP_USER`) | клиент, телефон, почта, сумма, формат, число людей, во сколько выдать ключ |
| Бронь снята / возврат | клиенту | что случилось и что делать |

Адрес, телефон, где брать и куда возвращать ключ, за сколько минут приходить: переменные `VENUE_ADDRESS`, `VENUE_PHONE`, `KEY_PICKUP`, `KEY_RETURN`, `ARRIVE_BEFORE_MIN` в `.env`.

```bash
npm run preview:mail   # сохранит все письма в docs/mail-preview/, ничего не отправляет
npm run check:mail     # проверит вход на SMTP
```

## Подключение ЮKassa

1. В личном кабинете ЮKassa возьмите `shopId` и создайте секретный ключ (Интеграция → Ключи API).
2. В `.env`: `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `BASE_URL=https://ваш-домен`.
   Используется сценарий «Виджет ЮKassa»: скрипт `https://yookassa.ru/checkout-widget/v1/checkout-widget.js`
   подгружается только в момент оплаты, цвета формы подогнаны под тёмную тему сайта.
3. Интеграция → HTTP-уведомления: адрес `https://ваш-домен/api/payments/yookassa`,
   события `payment.succeeded` и `payment.canceled`.
4. Если в магазине включены чеки (54-ФЗ): `YOOKASSA_RECEIPT=1` и код НДС `YOOKASSA_VAT_CODE`.
5. Сначала проверьте с тестовым магазином ЮKassa: карта `5555 5555 5555 4477`, любой будущий срок, CVC `123`,
   код 3-D Secure `123`. Потом поменяйте ключи на боевые.
6. Сайт должен открываться по HTTPS. Блокировщики рекламы иногда режут скрипт виджета: тогда клиент увидит подсказку.

Запросы к ЮKassa проверены тестами на подставных ответах. С настоящим магазином это ещё не пробовали.

## Подключение Google Календаря

1. В Google Cloud создайте проект, включите Google Calendar API.
2. Создайте сервисный аккаунт (IAM → Сервисные аккаунты), на вкладке «Ключи» создайте JSON-ключ
   и положите его в `secrets/google-service-account.json` (папка в git не попадает).
3. В настройках календаря «Студия — брони» → «Открыть доступ» добавьте адрес сервисного аккаунта
   (`...@...iam.gserviceaccount.com`, он есть в JSON-ключе) с правом «Вносить изменения в мероприятия».
   Календарь должен быть приватным: в событиях лежат телефоны и почты клиентов.
4. В `.env`: `CALENDAR_DRIVER=google`, `GOOGLE_CALENDAR_ID` (Настройки → «Идентификатор календаря»), путь к ключу.
5. Цвета: «⏳» жёлтые ждут оплаты, «✅» зелёные оплачены.

Запросы к Google проверены тестами на подставных ответах. С настоящим календарём это ещё не пробовали.

## Почта

Почта домена itb-company.com обслуживается Mail.ru: `SMTP_HOST=smtp.mail.ru`, `SMTP_PORT=465`.
Mail.ru пускает внешние программы только по **паролю для внешних приложений**
(Настройки почты → Безопасность → Пароли для внешних приложений), обычный пароль от ящика не подойдёт.
Проверка: `npm run check:mail`.

## Устройство

```
public/            сайт (HTML, CSS, JS) и страница 404
server/
  index.js         запуск, замок одного экземпляра, фоновая проверка
  app.js           HTTP: /api/* и раздача public/
  booking.js       слоты, бронь, отмена, сверка оплаты, возвраты
  payments.js      ЮKassa (виджет) и имитация оплаты
  validate.js      проверка заявки
  pricing.js       цены (считает только сервер)
  time.js          часовой пояс студии
  notify.js        письма и Telegram
  calendar/        memory (разработка) и google
scripts/           запуск тестов, проверка почты
test/              тесты (node:test)
docs/              схема, вайрфрейм, архив дизайнов
```

API:

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/config` | настройки, цены, «сегодня» в часовом поясе студии |
| GET | `/api/slots?from=&to=` | занятые часы по дням, не больше 14 дней |
| POST | `/api/book` | бронь из одного или нескольких промежутков (`ranges: [{date, hours}]`, блоки по `SLOT_HOURS` часов); при онлайн-оплате — токен виджета ЮKassa |
| GET | `/api/book/КОД?token=` | статус брони: `pending`, `paid` или `gone` |
| DELETE | `/api/book/КОД?token=` | отмена клиентом (только пока не оплачено) |
| POST | `/api/payments/yookassa` | уведомления ЮKassa |
